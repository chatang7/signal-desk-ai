# SIGNAL DESK FREE — 0원 예약 수집 대시보드

기존 SIGNAL DESK v2를 확장한 **무료 공개 소스 자동 수집 + 정적 대시보드** 구성입니다. 개인 컴퓨터가 꺼져 있어도 GitHub Actions가 매일 자동 실행됩니다. AI 유료 API, 별도 서버 결제, 카드 등록은 필요하지 않습니다. **처음 한 번의 GitHub 저장소 생성·게시 설정은 필요**합니다.

## 무엇이 자동인가?

- GitHub Actions 예약 실행: **매일 09:17 한국시간** (UTC 00:17). GitHub 정책상 정확한 분에 실행되는 것을 보장하지 않으며, 비활성 저장소의 예약 실행이 중지될 수 있습니다.
- 무료 공개 데이터를 Python 표준 라이브러리로 수집하고 `data/news.json`에 누적 저장(새로 게시된 글은 최근 7일 이내만 수집, 서버에 최근 35일 보관(최대 500건)).
- GitHub Pages에 대시보드와 데이터가 자동 게시됨. 브라우저를 꺼두어도 수집은 계속됩니다.
- 대시보드는 방문 시 게시된 JSON을 읽고 기존 검토 상태, 수동 메모, Discord 초안을 **그 브라우저의 로컬 저장소에서** 유지합니다.

### 데이터 소스 21개

- 공식 GitHub 릴리스 8개: OpenAI Codex, Gemini CLI, Claude Code, Transformers, vLLM, Ollama, ComfyUI, llama.cpp
- 공식 블로그 RSS/Atom 4개: OpenAI, Google AI, Kakao Tech, NAVER D2 (관련 AI 키워드로 필터)
- 연구: Hugging Face Daily Papers (논문 본문은 arXiv 원문 링크)

추가 출처 (Google DeepMind RSS는 GitHub 서버의 XML 응답 오류로 보류): Google Research·Hugging Face 블로그·Mistral AI·NVIDIA 개발자 블로그·Microsoft Research·GitHub Copilot 공식 변경사항·과학기술정보통신부 보도자료·AI타임스(2차 보도).

**뉴스 품질 규칙(v4)**: 발표일이 없는 글이나 7일이 지난 글은 신규 유입에서 제외합니다. 35일 이상 지난 공개 피드 데이터는 보관 목록에서 제외하고, URL·발표일·제목 유사도 및 버전 번호를 비교해 확실히 겹치는 기사만 묶습니다. 원문의 URL은 함께 보관합니다. 제목의 의미를 AI 모델로 분석하지 않으므로 같은 사건의 다른 표현은 여전히 일부 남을 수 있습니다. AI타임스는 원 발표가 아닌 **언론 보도**로 표시하며, 원문 1차 출처 검증은 별도입니다. 국내 기사 건수의 50% 비율은 강제하지 않으며 소스 실가용성에 따라 달라집니다.

소스별 오류는 앱의 **자동 수집** 탭과 `data/news.json`에 남으며, 소스에 문제가 있어도 이전 기록은 보존됩니다. 공식 릴리스 발표의 신뢰도와 발표 내용의 독립 검증을 혼동하지 않습니다. 비용·성능·기술 차이는 확인되지 않으면 빈칸/미정입니다. 제목·초록은 외부 원문 메타데이터입니다.

## 최초 1회 설치

### A. 가장 간단한 방법 (연결된 ChatGPT GitHub 사용)

1. [GitHub에서 저장소 만들기](https://github.com/new)를 엽니다. 이름 `signal-desk-ai`, **Public**, 기본 브랜치 `main`으로 만듭니다. 개인 메모나 토큰은 넣지 마세요.
2. ChatGPT와 GitHub 앱에 해당 저장소 접근을 허용한 다음 `signal-desk-ai 저장소 만들었어. 이 ZIP에 있는 프로젝트를 올려줘`라고 요청할 수 있습니다. 접근 권한이 없으면 파일 업로드가 불가능할 수 있습니다.
3. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택합니다.
4. **Actions → Collect AI news and publish dashboard → Run workflow**를 한 번 누릅니다. 처음 배포가 성공하면 `https://<GitHub사용자명>.github.io/signal-desk-ai/`에 접속합니다.

### B. 직접 업로드 (PC에서 git을 사용할 경우)

ZIP을 풀어 폴더로 이동한 다음, GitHub에 `signal-desk-ai`라는 **공개** 빈 저장소를 먼저 생성합니다. 아래의 `<GITHUB_USERNAME>`을 자신의 로그인명으로 교체하세요.

```bash
git init -b main
git add .
git commit -m "Initial free Signal Desk"
git remote add origin https://github.com/<GITHUB_USERNAME>/signal-desk-ai.git
git push -u origin main
```

그 뒤 A의 3~4단계를 진행하세요. 공개 저장소는 소스 코드와 자동 수집된 뉴스도 누구나 볼 수 있습니다. GitHub Free에서 Pages는 **공개 저장소**에 제공됩니다.

## 사용법

- 뉴스는 **뉴스 보관함**에서 확인합니다. 서버 피드에서 35일 초과 항목은 제외되지만 브라우저에 과거에 저장된 검토 기록은 자동 삭제하지 않습니다. 상태 변경·중복 후보 보기·필터·Discord 초안 편집은 기존 v2와 동일합니다.
- **자동 수집**에 표시되는 'GitHub 서버 수집 상태'는 자동화 결과입니다. 버튼 **저장된 피드 확인**은 수집을 실행하는 버튼이 아니라 서버가 기록한 결과를 다시 읽는 버튼입니다.
- `공개 API 수동 보충` 버튼은 방문자의 브라우저에서 기존 v2 방식으로 직접 추가 수집합니다. 백그라운드 수집과 별도입니다.
- 예전 HTML에서 수정했던 기사/메모를 새 웹사이트로 옮기려면 이전 대시보드의 **운영 설정 → JSON 백업**, 새 사이트의 **가져오기** 기능을 사용하세요. 브라우저의 저장 주소(origin)가 바뀌면 자동 이전되지 않습니다.
- 무료·저비용 필터는 **확인된 가격 등급에만** 적용됩니다. 공식 데이터가 무료라고 확증하지 못하면 '미정'이므로 필터에 표시되지 않습니다.

GitHub Actions 실행은 가끔 지연·실패할 수 있고, 오래 활동이 없는 공개 저장소에서 예약 워크플로가 자동으로 비활성화될 수 있습니다. Pages 사용과 스케줄 무료 제공 정책은 GitHub에서 언제든 바뀔 수 있으니 [GitHub Pages 문서](https://docs.github.com/en/pages/quickstart)와 [GitHub Actions 문서](https://docs.github.com/en/actions)를 확인하세요.

- 개인 API 키·토큰·Discord 웹훅을 소스에 넣지 않습니다.

- 웹 브라우저의 로컬 검토 상태·메모는 `data/news.json`에 포함되지 않으며 서버로 올라가지 않습니다.
- 그러나 공유 PC 또는 브라우저 정리 시 메모가 유실될 수 있으므로 정기 JSON 백업을 권장합니다.
## Discord 자동 브리핑 설정 (v5)

별도 Discord Bot 토큰이나 호스팅 서버는 필요하지 않습니다. **Discord 채널 관리 권한**으로 발급한 웹훅 URL 하나를 GitHub Secret에 저장합니다.

1. 원하는 Discord 서버/채널에서 **채널 편집 → 연동(Integrations) → 웹훅(Webhooks) → 새 웹훅**을 만들고 해당 채널의 **웹훅 URL 복사**를 누릅니다. 일반 채팅 채널을 추천합니다(포럼·미디어 채널은 추가 thread 설정이 필요하므로 지원하지 않음).
2. GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 이름 `DISCORD_WEBHOOK_URL`, 값에는 복사한 전체 웹훅 주소를 입력합니다. 이 URL에는 비밀 토큰이 들어 있으므로 채팅, 공개 코드, 이슈에 붙이지 마세요.
3. 그러면 다음 정기 실행(한국시간 **09:17**)부터 자동 전송이 시작됩니다. GitHub 예약 실행 누락에 대비해 **09:47**에도 보조 실행합니다. GitHub Actions 스케줄은 지연되거나 누락될 수 있으며, 보조 실행 역시 완전한 보장은 아닙니다. 실제 중복 게시를 막기 위해 기존 7시간 간격·하루 1회 제한 및 발송 이력을 그대로 적용합니다.
4. 테스트로 실제 채널에 보내려면 **Actions → Collect AI news (free) → Run workflow** 메뉴에서 `discord_send` 체크박스를 **직접 켜고** 실행하세요. 체크하지 않은 수동 실행이나 코드 변경(push)만으로는 Discord에 게시하지 않습니다.
5. 웹훅을 삭제하거나 메시지를 중지하려면 GitHub Secret `DISCORD_WEBHOOK_URL`을 삭제하면 됩니다. Discord 설정에서 웹훅을 삭제해도 됩니다.

**운영 규칙:** 새롭고 중요도가 높은 브리핑 **하루 최대 1회, 가장 중요한 뉴스 1건**만 상세한 메시지 하나로 전달합니다. 적합한 소식이 없으면 발송하지 않습니다. 3일을 초과한 뉴스는 제외합니다(발표일만 제공되는 피드는 날짜 기준, 정확히 72시간을 보장하지 않음). 7시간 이내 재게시 및 같은 한국 날짜 1회 초과 발송을 막습니다. 이미 보낸 아이템 ID는 공개 저장소의 `data/discord_state.json`에 기록합니다. 키, 웹훅 URL, 기사 본문은 해당 파일에 저장하지 않습니다. 정상 메시지 ID를 Discord API(`wait=true`)로 확인한 후에만 기록하고, 429 제한에는 짧게 대기 후 재시도합니다. 포맷 오류와 인증 오류는 안전하게 실패합니다.

**한계:** 채널의 메시지 전송 성공 직후 GitHub 상태 저장까지 실패하거나 네트워크 응답이 유실되는 경우 동일 내용을 다시 보낼 가능성은 0으로 보장할 수 없습니다. 웹훅 전송은 '최선의 중복 방지(best effort)'입니다. Gemini의 내용 역시 독립 사실 검증을 대체하지 않습니다. GitHub Actions 무료 쿼터와 Google API 무료 할당량은 계정/정책에 따라 달라집니다.

**코드 검증:** `python -m unittest discover -s tests -p 'test_*.py' -q` 로 전송 선택, 중복 기록, 시간 제한, 멘션 방지 등을 네트워크 연결 없이 테스트합니다.


## Discord 진행자 말투 — 가시춘풍 균형형

SIGNAL DESK는 사실 위주의 뉴스 요약과 별도로 **감정이 있는 가상 진행자의 감상**을 Discord 메시지에 표시합니다.

- **호기심:** 새로운 연구·오픈소스·도구를 발견하면 기대감을 보이되 성능을 미리 단정하지 않음
- **냉소:** 성능 비교와 과장된 발표는 증거·비교 조건을 먼저 따짐
- **진지함:** 보안과 정책·규제는 농담을 줄이고 위험·책임을 강조함
- **원작 설정의 희소한 언급:** 충분한 기사 누적 후 관련 기사가 있을 때만 홍원 약 18건당 최대 한 번, 홍루 약 36건당 최대 한 번의 짧은 독백. 첫 몇 회차에는 넣지 않음. 실제 등장 빈도는 관련 주제의 유무에 따라 더 적을 수 있음. **직접적인 원작 대사 복제·허구의 인물 발언·중대한 스포일러 없음**.
- 언론 보도·원문 사실과 가상 진행자의 감상은 Discord 메시지에서 분리해 표기. Gemini가 새 기사 분석을 만들 때 짧은 진행자 도입·논평도 함께 작성하나, 허구의 수치·근거 없는 성과는 생성하지 않도록 지시하고 수치 검증을 수행함.
- 과거 Gemini 분석 캐시는 사실 요약을 보존한 채 진행자 말투 필드만 **실행당 최대 4회** 순차적으로 채움. API가 없거나 오류가 나면 분위기별 기본 멘트를 사용하고 이전 요약은 유지함.
- 말투 변경은 새로운 게시분에 적용되며, 이미 Discord에 보낸 글을 다시 게시하거나 수정하지 않음. 코드 변경(push)만으로도 Discord 채널에 발송하지 않음.

메시지 문체는 원작 캐릭터의 성격적 특징을 참고한 **비공식 팬 스타일**이고, 공식 게임 스크립트나 캐릭터의 실제 발언이 아닙니다.


### Discord 제목 앞 유형 표시

브리핑 머리말에는 `🌸`를 한 번 사용하고, 각 기사 제목에는 유형에 맞는 이모지를 **한 개만** 붙입니다. 예: `🧩 [오픈소스] 기사 제목`, `📄 [논문] 기사 제목`, `🗂 [데이터셋] 기사 제목`, `🔄 [업데이트] 기사 제목`. 기사 중요도(`상세` 또는 `간략`)는 카드 하단 출처 정보에만 남깁니다. 본문 소제목에서는 이모지를 제거하고 가시춘풍의 성격은 도입과 평가 문장으로 전달합니다.

- 뉴스 구분은 **주제, 원문 URL, 제목·요약의 명시적인 기술 유형**을 우선 사용하며, 근거가 모호하면 `📰 [뉴스]`로 표시합니다.
- GitHub Copilot의 변경 기록(`github.blog`)은 GitHub 소식이라는 이유만으로 오픈소스로 분류하지 않습니다. 블로그에서 다룬 연구를 실제 논문 URL 없이 무조건 논문으로 표시하지도 않습니다.
- 이는 제목 표시 기능이며, 독립적인 오픈소스 라이선스 검증·논문 심사 여부·프로그램 설치 가능 여부를 자동으로 증명하지 않습니다.
- 제목 구분 추가는 이후 새로 게시되는 Discord 메시지에만 적용합니다. 이전 메시지와 중복 전송 장부는 변경하지 않습니다.

## Discord 뉴스 전달 방식: C형 혼합 브리핑

- **상세형 1건:** 가장 중요한 소식 하나를 첫 카드에 배치합니다. 뉴스가 1건뿐이어도 상세형으로 전달합니다.
- **Discord에서는 간략형을 보내지 않음:** 가장 중요한 1건만 상세형으로 전달하며, 그 밖의 후보는 웹 브리핑에 남깁니다.
- **관련 이미지 1장:** RSS 개별 기사 이미지(`media:content`, `media:thumbnail`, `enclosure`)를 우선하고, 없거나 접근이 불가능하면 **공식 원문**의 `og:image`/`twitter:image`를 확인합니다. HTTPS·공식 도메인 또는 지정된 이미지 CDN·이미지 MIME·8MB 이하 조건을 만족한 URL 하나만 Discord 카드 하단에 붙입니다. 공식 이미지가 없거나 검증에 실패하면 **기존 텍스트 브리핑만 발송**합니다. 직접 이미지를 생성·변형·재호스팅하지 않으며 원문 링크는 유지합니다.
- **가시춘풍 짧은 소제목:** 상세형에서 `무슨 소란이지?`, `뭐가 다른데?`, `눈여겨볼 점`, `쓸모는 있겠지?`, `실속은?`, `내 평가` 등을 사용합니다. 비교 근거가 없는 경우 해당 비교 항목은 쓰지 않고 없는 숫자를 채워넣지 않습니다.
- **최신성 우선:** 뉴스 발표일을 기준으로 오늘·어제 소식을 우대하며, 일반적으로 최근 3일 내 공개된 기사만 Discord 후보에 포함합니다. 최소 1건의 미전송 중요 뉴스가 있어야 게시하며, 억지로 기사를 채우지 않습니다.
- **실용성 우선:** 기존 중요도 점수에 공개 출처, 오픈소스·무료·Windows·로컬 활용 가능성, 최신성을 반영해 우선순위를 조정합니다. 언론 기사보다 원문 링크가 있는 내용을 우대합니다. 값이 '미확인'인 가격·성능은 사실처럼 쓰지 않습니다.
- **Discord 길이 제한:** 최대 1개의 임베드에 총 6,000자 이하로 구성합니다. 넘칠 때는 장황한 부가 필드를 제거합니다.
- **중복 전송 방지 유지:** 이미 보낸 기사 ID를 기록하며, GitHub 코드 수정·푸시·일반 수동 실행은 Discord 메시지를 전송하지 않습니다. `--dry-run`은 게시 이력을 변경하거나 웹훅을 호출하지 않고 현재 피드로 미리보기만 생성합니다.

이 변경은 **Discord의 뉴스 전달 형식과 선별 우선순위**에 관한 것입니다. 조사 범위 전체를 넓히는 작업과 X·Threads·Reddit 등 커뮤니티 수집의 합법적·기술적 연결은 아직 별도 과제입니다.


### Discord 웹훅 실제 출력 테스트 (중복 방지 기록과 분리)

Discord 메시지의 표시 이름은 정상·테스트 전송 모두 **`[가시춘의 홍원 가십]`**으로 통일합니다. 테스트 여부는 별도의 `🧪 [테스트 전송]` 안내 문구로 구별합니다. 과거 메시지의 표시 이름은 소급 변경하지 않습니다.

새로운 말투·뉴스 레이아웃을 즉시 확인하려면 GitHub Actions → `Collect AI news (free)` → **Run workflow**에서 **`discord_test_send`만 체크**하고 실행하세요. 예전 `discord_send`는 정상 게시용입니다. 테스트와 정상 게시를 함께 체크해도 테스트만 전송됩니다.

- 테스트 메시지는 `🧪 [테스트 전송 — 실제 뉴스 알림 아님]`으로 표시되고 1개 뉴스 카드만 한 번 전송합니다.
- 최신 3일 이내의 중요 뉴스 1개 이상이 있어야 테스트합니다. 이미 게시된 기사를 재사용할 수 있습니다.
- 테스트는 **7시간 간격·하루 최대 1회 정상 발송 제한을 변경하거나 해제하지 않습니다.** `data/discord_state.json`에 테스트 전송을 기록하지도 않습니다.
- 테스트 옵션은 사용자가 체크할 때에만 실행됩니다. 소스 수정에 따른 자동 푸시로는 Discord에 게시되지 않습니다.
- 웹훅 URL을 채팅·코드·실행 로그에 노출하지 마세요. 테스트를 반복하면 채널에 매번 새 테스트 메시지가 생기므로 필요할 때만 실행하세요.
